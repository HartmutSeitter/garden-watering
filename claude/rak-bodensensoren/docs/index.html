RAK WisBlock Bodensensoren

Zwei energieautarke LoRaWAN-Nodes zur Erfassung von Bodenfeuchte, Bodentemperatur und elektrischer Leitfähigkeit (EC). Betrieb mit 18650-Akku + Solarpanel, Datenübertragung via TTN nach InfluxDB / Node-RED.

Antenna-Switch Fix

Der RAK4631 benötigt einen manuellen Register-Write, damit der DIO2-Pin den Antenna-Switch korrekt steuert — ohne diesen Fix wird kein LoRa-Signal gesendet:

// In setup(), nach lora_rak4630_init():
uint8_t dio2_config = 0x01;
SX126xWriteRegisters(0x058B, &dio2_config, 1);

Join-Flag — volatile

Kritisch: Das Join-Flag muss als volatile bool deklariert sein. Ohne volatile optimiert der Compiler den Wert weg — loop() sieht immer false und sendet nie, obwohl der Join in TTN sichtbar ist. 
static volatile bool joined = false;

void lorawan_has_joined_handler(void) {
    joined = true;  // Callback aus IRQ-Kontext
}

void loop() {
    if (!joined) return;  // kein Send vor bestätigtem Join
    // ...
}

BufferedStream — Atomarer RS485-Versand

Modbus RTU erfordert, dass alle Bytes eines Frames innerhalb von maximal 1,5 Zeichen-Längen aufeinanderfolgen (3,1 ms bei 4800 Baud). FreeRTOS-Task-Switches zwischen einzelnen write()-Aufrufen würden den Frame unterbrechen. Die BufferedStream-Klasse puffert alle Bytes und sendet sie in einem einzigen DMA-Transfer:

class BufferedStream : public Stream {
    // Puffert alle write()-Aufrufe
    // flush() → einmaliger DMA-Transfer via Serial1.write(buf, len)
};

void postTransmission() {
    modbusSerial.flush(); // atomarer DMA-Transfer
    delay(5);             // Stop-Bit physisch ausgesendet lassen
}

TTN Payload Decoder (JavaScript)

function decodeUplink(input) {
  var bytes = input.bytes;
  return { data: {
    Bat_f:           (bytes[0] << 8 | bytes[1]) / 1000,
    TempC_DS18B20_f: (bytes[2] << 8 | bytes[3]) / 10,
    water_SOIL_f:    (bytes[4] << 8 | bytes[5]) / 100,
    temp_SOIL_f:     (bytes[6] << 8 | bytes[7]) / 100,
    conduct_SOIL_f:   bytes[8] << 8 | bytes[9]
  }};
}

Hardware-Watchdog

Der nRF52840-interne WDT wird mit 120 Sekunden konfiguriert. 60 Sekunden waren zu kurz — LoRa TX + beide RX-Fenster (RX1 + RX2) können zusammen mehrere Sekunden dauern, dazu kommen Modbus-Timeouts.

void initWatchdog() {
    NRF_WDT->CONFIG      = 0x01;       // läuft auch im Sleep
    NRF_WDT->CRV         = 32768 * 120; // 120 Sekunden
    NRF_WDT->RREN        = 0x01;       // Reload-Register 0
    NRF_WDT->TASKS_START = 1;
}

// In loop() UND nach jedem Modbus-Read:
void feedWatchdog() {
    NRF_WDT->RR[0] = WDT_RR_RR_Reload;
}
Der WDT wird an zwei Stellen gefüttert: am Anfang von loop() und direkt nach node.readHoldingRegisters(), da der Modbus-Call blockierend ist und bis zu mehrere Sekunden dauern kann.

Adaptives Sendeintervall

Das Sendeintervall passt sich dynamisch an die Batteriespannung an. Erster Send erfolgt 1 Minute nach Boot.

BatteriespannungIntervallBegründung
≥ 4,0 V Normal20 MinutenVollgeladen / Solar aktiv
3,9 – 4,0 V Gedrosselt30 MinutenMittlerer Ladestand
< 3,9 V Sparmodus60 MinutenPuffer vor Ausfall bei ~3,75 V
 
uint16_t batMV = readBatteryMV();
if      (batMV < 3900) sendInterval = 3600000; // 60 min
else if (batMV < 4000) sendInterval = 1800000; // 30 min
else                   sendInterval = 1200000; // 20 min

Batterie-ADC Kalibrierung

uint16_t readBatteryMV() {
    analogReference(AR_INTERNAL_3_0);
    analogReadResolution(12);
    float raw = analogRead(WB_A0);   // WB_A0 = P0.05 / AIN3
    analogReference(AR_DEFAULT);
    analogReadResolution(10);
    // Spannungsteiler 1:2, empirisch kalibriert
    return (uint16_t)(raw * 2571.0 / 4096.0 * 2.0);
}

  7. In Node-RED: MQTT-Subscribe für neues TTN-Topic, InfluxDB-Write mit neuem Measurement.

Bekannte Probleme & Lösungen

Node-02 — Hänger nach einiger Zeit

Symptom: Join in TTN sichtbar, danach kein einziger Uplink.
Ursache 1: volatile fehlt am Join-Flag → Compiler-Optimierung liest immer false.
Ursache 2: Schlechter Batteriehalter-Kontakt → Spannungseinbrüche → RAM-Korruption.
Lösung: static volatile bool joined, WDT auf 120s, Batteriehalter getauscht (Mai 2026).

Dragino LSE01 (separater Sensor)

Problem: Nach Batteriewechsel alle Werte = 0, kein TX-Signal auf RS485.
Diagnose: UART-TX-Pin des LSE01-MCU defekt (ESD-Schaden beim Batteriewechsel).
Wichtig: LSE01 verwendet proprietäres Protokoll — nicht Modbus RTU, nicht mit RAK5802 kompatibel.
Status: Support kontaktieren oder Gerät ersetzen. Die originale Bodensonde ist intakt.
